# A股年报（2026 中报）RAG 问答系统

对 14 家 AI 产业链公司的 2026 年半年度报告做检索增强问答：提问 → 向量 + BM25 混合检索 →
本地 Qwen3-Embedding 排序召回 → DeepSeek 依据召回原文作答，答案中每个论断带可点击的
引用 `[公司·报告期·章节·页码]`，侧边栏同步显示本次召回的 top10 块及相似度分数。

## 一、快速开始

> **仓库里没有 PDF 和索引产物**（共约 60MB，理由见 `.gitignore` 内的注释）：原始 PDF 是
> 老师发的资料，索引与可视化数据都由下面两条命令重新生成，页数/块数与本文档记录的
> 2590 页 / 3007 块一致。只拿到本仓库时，把 14 份 PDF 放进仓库根目录（`build_index.py` 用
> `ROOT.glob("*.pdf")` 发现它们，文件名任意——公司简称与代码是从 PDF 正文首页读的，不是
> 从文件名），再按 1)、2) 重跑即可。第 2 步生成的可视化数据是 `web/visual.html` 的数据源，
> 不做第 2 步则只有问答页可用。

```bash
# 0) 装依赖（Python 3.10+）
pip install -r requirements.txt

# 1) 建索引（只需跑一次，产物落在 data/）
python build_index.py

# 2) 生成可视化页面的数据（只需跑一次，约 30s，产物落在 web/）
python build_viewer.py

# 3) 一条命令起服务，浏览器打开 http://127.0.0.1:8077
python serve.py
```

两个页面：

| 地址 | 内容 |
|---|---|
| `http://127.0.0.1:8077/` | 问答页：提问、带引用的流式答案、侧边栏 top10 召回 |
| `http://127.0.0.1:8077/visual.html` | 可视化页：语料基本信息 + 财报语义地图 + 每次召回的相关原文 |

Windows 上也可以直接双击 `start.bat`（会先检查索引是否已建好，再起服务）。
服务监听 `0.0.0.0:8077`（可用环境变量 `RAG_PORT` 改端口）。

`web/visual.html` 也可以**直接双击打开**（`file://`），见第六节。

**建索引与服务是分开的**：建索引只跑一次，产物全部落在 `data/`，之后每次启动只跑
`serve.py`，加载现成的向量矩阵与倒排索引即可。启动时会**预热编码模型**（本机约 40s），
因此第一个提问不需要等模型加载：预热后检索耗时 0.1~0.3s，整轮问答 2~3s。
解析与编码也分成两个阶段，可以分别重跑：

```bash
python build_index.py --stage parse     # 14 份 PDF 解析 + 切块，约 55s（8 进程）
python build_index.py --stage embed     # 向量编码 + BM25，可反复重跑
```

编码阶段每 640 块落一次断点（`data/index/emb.partial.npy`），中途被中断后重跑会
自动从断点继续，不必从头再来。

**GPU 加速**：有 CUDA 时自动用 GPU（`torch.cuda.is_available()`），0.6B 模型以 fp16
加载；无 GPU 则回退 CPU（建索引会明显变慢）。实测本机 RTX 3060 Laptop（6GB）上
fp16 编码约 3000 块用 14 分钟；batch 取 32 而非 64，并在 batch 内**按文本长度分桶**
排序，避免短块被 padding 到长块的长度而白算。

| 变量 | 用途 | 是否必需 |
|---|---|---|

| `DEEPSEEK_API_KEY` | DeepSeek 密钥，**只在服务端读取，绝不下发浏览器** | 问答必需 |
| `DEEPSEEK_BASE` | 默认 `https://api.deepseek.com` | 可选 |
| `DEEPSEEK_MODEL` | 默认 `deepseek-chat` | 可选 |
| `RAG_PORT` | 服务端口，默认 `8077` | 可选 |

### 跑起来需要在本机额外准备三样东西（代码之外）

| # | 需要什么 | 从哪来 | 什么时候要 | 本仓库是否包含 |
|---|---|---|---|---|
| 1 | 14 份中报 PDF，共 26MB | 老师发的资料 | 只在 `build_index.py` 建索引时 | ❌ 体积大且是原始资料，见 `.gitignore` |
| 2 | Qwen3-Embedding-0.6B 模型，约 1.2GB | HuggingFace / ModelScope 的 `Qwen/Qwen3-Embedding-0.6B`，下到本地任意目录后用 `EMBED_MODEL_DIR` 指过去 | **建索引与起服务都要**——提问也要先编码成向量才能检索 | ❌ 1.2GB 不进 git |
| 3 | `DEEPSEEK_API_KEY` | DeepSeek 控制台 | 只在提问作答时 | ❌ 密钥按题目要求只走环境变量 |

第 2 项常被忽略：**只要起服务就缺不了它**，不存在"只跑检索不用模型"的路径。
`build_index.py` 和 `serve.py` 都会在启动前检查它，未设置或路径不存在时直接给出上面
这段提示后退出（而不是等预热阶段抛栈）。

若希望对方**下载后跳过建索引**立刻可用，把 `data/chunks.jsonl`、`data/pages.jsonl`、
`data/index/emb.npy`、`data/index/bm25.pkl`（合计约 28MB）一并交付即可，之后只需
`python serve.py`；第 2、3 项仍然必需。要连"可复现建索引"一起满足，则再带上 PDF。

## 三、解析与切块

**解析**（`rag/parse.py`）

- 正文：PyMuPDF 取文字坐标（`get_text("dict")`），按块、行、span 还原阅读顺序；
  同一视觉行内 span 间距大于 20pt 时插入 `|` 分隔，用于还原无框线的多列排版。
- 表格：pdfplumber `find_tables()` 取表格，单元格清理后输出 **Markdown 表格**
  （表头完整、单元格按行列对齐、去掉全空行/列、单格首行识别为表标题）。
- 分工：先用 pdfplumber 的表格区域 bbox 把正文里落在表格内的文本块剔除，再按
  阅读顺序（y 坐标）把「正文段落 + 表格」重新拼成一页的结构化文本——避免
  同一份内容既以散文本又以表格出现两遍。
- 跨页表格：上一页末表紧贴页底、本页首表紧贴页顶、且两表列数一致时判定为同一张
  跨页表，把续页行并入起页。**剔除正文用原始 bbox、渲染用合并后的表格**，
  否则续页内容会被渲染两次。合并后该表的**页码区间跟着扩展到续页**
  （如 p56–p57），否则引用页码会漏掉续页上的数字。
- 页眉页脚：统计页眉/页脚带内出现率 ≥50% 的文本块 + 页码正则 + 跑马灯标题模式，
  三类一起剔除。

**章节**（`rag/parse.py:detect_sections`）

先识别目录页（含「目录」且有 ≥4 个带页码的「第X节」行），再从正文按标题正则
`^第\s*[一二三四五六七八九十]+\s*节` 定位各章起点，得到「章节 → 物理页码区间」。
目录页本身不建索引块（纯导航信息），但页面文本仍保留在 `data/pages.jsonl` 供溯源。
第一章之前的封面/重要提示归入「前置（封面与重要提示）」。

**页码**：一律使用 **PDF 物理页码**（自封面第 1 页起算）。
每页同时记录了页面上印刷的页码（`printed_page` 字段），**两者可能存在偏移**
（封面、目录的排版差异所致），界面底部也对此做了提示。

**切块**（`rag/chunker.py`）

- 章节边界优先：每个块不跨章节。
- 块大小 ~700 token（用 Qwen3 tokenizer 精确计数），超长**正文**按句切分。
- 重叠 10%：新块开头重复上一块尾部约 70 token 的内容；若尾部本身是超大元素
  （例如一张 2000 token 的表），则跳过重叠，否则整张表会被复制进下一块。
- **表格整块不切**：表格作为不可分割的原子元素参与 token 累积，进也整块、出也整块。
  表格不强制独占一块——财务数据表前后往往紧跟着「单位：千元」「主要财务指标」
  这类说明文字，放在同一块里上下文更完整（单位陷阱正是靠这一点解决的）。
- 收尾清理：纯页码块（如 `61 / 167`）直接丢弃；不足 60 token 的短块并入同章节的
  前一块（财务报表章节里大表一张接一张，表缝里常留下一行表题或「不适用」，
  单独立块没有信息量还会污染召回）。
- 每块元数据：`{公司, 代码, 报告期, 章节, 页码范围, chunk_id}`，另有 `citation`
  引用串、`has_table` 标记与 `global_index`。

**实测规模**：14 份报告共 2590 页 → **3007 个块**（表格块 2043、正文块 964），
中位长度约 670 token。

## 四、检索（`rag/retriever.py`）

严格按题目要求，**不做重排、不做查询改写、不引入第三路召回**。

### 被索引的文本 = 元数据前缀 + 块正文

两路检索用的都**不是**块正文本身，而是：

```
公司 代码 报告期 章节
{块正文}
```

原因：解析阶段剔除了页眉页脚，而公司名恰好主要出现在页眉页脚里，于是块的
正文中几乎不再出现自己公司的名字（全库「寒武纪」只出现在 29 个块里）。
后果是「寒武纪2026年上半年营业收入是多少」这种点名公司的提问，两路都无法用
公司名限定范围，只能靠各家共有的「增长/同期/上年」打分，前排会混进别家公司
——实测该提问的 BM25 第一名是佰维存储，融合后 top10 里甚至找不到含正确答案的块。

加上前缀后每个块都自带公司名与章节，点名提问就能命中。前缀放在最前面，
长块被 `max_seq_length` 截断时它一定保留。**展示给用户的块原文不受影响**：
`chunks.jsonl` 的 `text` 字段仍是纯正文，界面上展开看到的就是它。

> 这是**索引侧**的处理（决定"把什么放进索引"），不是查询改写，也不是重排。

### 向量路

- 模型：本地 `Qwen3-Embedding-0.6B`，路径读环境变量 `EMBED_MODEL_DIR`。
- **query 加 instruction，document 不加**（Qwen3-Embedding 官方用法）：

  ```
  Instruct: 给定一个关于A股上市公司半年度报告的中文问题，检索能够回答该问题的财报原文段落
  Query: {用户问题}
  ```

- 输出 **L2 归一化**向量，因此内积即余弦相似度。
- 取 **top20**。

### BM25 路

- jieba 精确模式分词（查询与文档用同一函数），保留数字与双字以上实词，去掉高频虚词。
- 自建倒排索引 `term → [(doc_id, tf)]`，参数 k1=1.5、b=0.75。
- 取 **top20**。

### 融合规则：RRF

两路各取 top20，**并集**后按 Reciprocal Rank Fusion 计分（k=60）：

```
score(d) = Σ_r 1 / (k + rank_r(d))      k = 60, r ∈ {向量, BM25}
```

只对出现在某一路 top20 内的文档计分；按 score 降序取 **top10** 作为最终上下文，
交给 DeepSeek。侧边栏会同时展示每个块的 RRF 分数、向量余弦、BM25 分数及各自名次，
并把 `in_vector` / `in_bm25` 标记出来，便于观察两路的贡献。

## 五、问答与页面

- 回答模型：DeepSeek（`https://api.deepseek.com/chat/completions`），密钥只走环境变量，
  **不下发浏览器**。
- 服务端把 top10 块的原文与引用串拼进 prompt，要求模型每个论断后附
  `[公司·报告期·章节·页码]`，并禁止编造与先验补充。
- 前端（`web/index.html`）：提问框；答案流式渲染，引用渲染成可点击的 chip，
  点击后高亮并展开侧边栏对应块的原文；侧边栏显示本次召回 top10 的元数据与相似度分数；
  答案先到召回结果（SSE `retrieval` 事件）再流式输出答案（`delta` 事件）。

## 六、可视化页面（语料信息 + 语义地图 + 召回原文）

`web/visual.html` —— 除问答外的第二个页面：左侧是**财报语义地图**与**语料基本信息**，
右侧是**提问框**、流式答案，以及**每次提问召回的相关原文**（每块带 RRF/向量/BM25 分数、
可展开原文、可一键在地图上定位）。

数据由 `python build_viewer.py` 一次性生成到 `web/`（约 30s）：

| 文件 | 大小 | 内容 |
|---|---|---|
| `viewer_meta.js` | ~460KB | 语料信息 + 两套二维坐标 + 逐块轻量元数据 |
| `viewer_chunks.js` | ~5.9MB | 全部块原文（页面**按需**加载，只有点地图上的点时才拉） |

### 两套坐标（`viewer_meta.js` 里的 `xyRaw` / `xyRes`）

地图默认画 `xyRaw`：直接对 `emb.npy` 的原始向量 PCA(50) → t-SNE(2)。
**这是检索真实使用的空间**，所以「本次召回的 10 块」只有画在它上面才与打分对应。

但画出来是**14 个公司孤岛**，不是语义团簇。原因在第四节的元数据前缀：实测
**公司身份解释了 42.8% 的嵌入方差，章节只解释 8.8%**（按「1 − 组内平方和/总平方和」算），
原始向量里 1-近邻同公司率 **99.1%**。所以：

- **不按公司着色**——位置已经 99% 准确地把公司分开了，颜色再编码一遍公司等于浪费一个通道；
  而且 14 个分类色在散点图上过不了对比度与色觉校验。改为**按 3 个语义组着色**
  （财务报告 1997 块 / 管理层讨论与分析 444 块 / 其他 566 块），公司身份交给位置与
  14 个质心文字直标。
- 提供 `xyRes` 作为**分析视图**：先减掉各公司质心、再按行 L2 归一化后同样降维。
  同公司最近邻率从 99.1% 降到 **31.4%**，跨公司的主题云才显出来（同章节率反而从
  0.887 升到 0.910）。切过去时页面会说明它是分析视图、召回环与它没有对应关系。

坐标可复现：`random_state` 钉死，连跑两次 `sha256sum web/viewer_*.js` 逐位一致
（构建时间与耗时只打到控制台，不进产物）。

### 两种打开方式

| 方式 | 地图 + 语料信息 | 提问 |
|---|---|---|
| 服务托管 `http://127.0.0.1:8077/visual.html` | ✅ | ✅（同源，最稳妥） |
| **双击** `web\visual.html`（`file://`） | ✅ 零网络请求 | ✅（需本地服务在跑，见下） |

双击能用是因为数据做成了**经典脚本 + 全局变量**（`file://` 下 `type="module"` 与
`fetch('./x.json')` 都会被浏览器拒），且小的一份必须加载、大的一份用到再加载。
提问则必须由本机的服务来跑：浏览器里跑不了 0.6B 的嵌入模型，**DeepSeek 密钥也只在
服务端环境变量、不下发浏览器**。

为此服务端加了 CORS 白名单，只放行 **`Origin: null`**（`file://` 页面的 Origin 就是
这个字面量）——比 `["*"]` 严格得多，`https://evil.com` 的 Origin 不会变成 `null`，
所以任意站点的网页都调不到这个接口（已实测：`Origin: null` 的预检 200 +
`Access-Control-Allow-Origin: null`，`https://evil.com` 的预检 400 且不带该头）。
另外回了 `Access-Control-Allow-Private-Network: true`，应对 Chrome 的本地网络访问限制。

连不上服务时，提问区不会把原始报错糊上来，而是给出可点击的指引
（起服务、或用 `/visual.html` 地址打开）；地图与语料信息不受影响。

> 顺带一提：这个接口被当成代理最多是**烧掉调用额度**，不会泄露密钥——
> 密钥始终在服务端，请求体与响应里都没有它。

### 前端自检（可选，需 Node）

```bash
node verify_viewer.js      # 25 项：产物自洽、二分定位、引用串、渲染与相机路径
```

它在一个最小 DOM 桩里真跑 `visual.html` 的内联脚本，再拿 `data/chunks.jsonl` 交叉核对
逐块推断出的公司与引用串（3007 个块逐个比对）。浏览器里的实际观感与真实 SSE 链路
不在它的覆盖范围内。

## 七、评测

`eval_qa.txt` —— 10 道题（2 道跨公司全景题 + 8 道公司内题，数字题为主）及系统的
实际作答与引用溯源。每题除答案外还输出：

- **本次召回 top10**：每块的 RRF 分数、向量/BM25 分数与各自名次、引用串。
- **标准答案所在块在本轮检索中的位置**：把标准答案定位到具体块（按 公司+章节+
  答案中的关键数字 定位，不写死 chunk_id），再报出它在两路召回与 RRF 融合中的
  实测名次。这一栏是为了把**「检索没召回」**和**「召回了但模型没用上」**分开
  ——两者要改的地方完全不同，只看最终答案分不出来。

**结果**：关键数字全部命中 **6~7/10**。

| 题 | 类型 | 判定 | 标准答案 | 金块在本轮检索中的名次 |
|---|---|---|---|---|
| 1 | 全景 | ✓ | 佰维存储营业收入同比 298.10% | 融合第 2 名 |
| 2 | 全景 | ✗ | 摩尔线程研发占收入比 44.30% | 未进两路 top20 |
| 3 | 公司内 | ✓ | 寒武纪营收 5,995,573,619.61 / +108.13% | 融合第 3 名 |
| 4 | 公司内 | ✓ | 寒武纪归母净利 2,310,912,080.33 / +122.61% | 融合第 24 名（落榜仍答对） |
| 5 | 公司内 | ✓ | 中芯国际营收 38,635,115 千元 / +19.4% | 融合第 4 名 |
| 6 | 公司内 | ✓ | 中芯国际毛利率 23.2%（上年 21.9%） | 融合第 2 名 |
| 7 | 公司内 | ✗ | 拓荆归母净利同比 +1,324.10% | 融合第 22 名（落榜） |
| 8 | 公司内 | ✓ | 摩尔线程研发占收入比 44.30% / −35.03pct | 融合第 1、2 名 |
| 9 | 公司内 | ✗ | 新易盛归母净利 7,529,168,039.39 / +90.98% | 融合第 12 名（RRF 差 0.00023） |
| 10 | 公司内 | ✗（波动） | 江波龙营收 24,088,363,284.95 / +136.26% | 未进两路 top20 |

**失分的第 2、7、9 题与波动题第 10 题的共性：**

1. **固定 top10 的召回边界。** 按题目要求，融合规则固定为「向量 top20 ∪ BM25
   top20 → RRF(k=60) → top10」，且不允许重排、查询改写或其他多路召回。10 个
   上下文槽位对多数公司内题够用（第 3、5、6、8 题的金块排在融合第 1~4 名），
   但两处会擦线：
   - **跨公司全景题**：要比 14 家公司的同一指标，10 个块装不下 14 家的同类数据
     （第 2 题）。系统如实说明覆盖不足，只给出它覆盖到的公司中的最高者，未编造
     全局结论。
   - **关键数字只在边缘块里出现**：第 9 题金块向量第 6 名、BM25 未进前 20，
     RRF=0.015152，而 top10 门槛是 0.015385 —— **差 0.00023 落榜**（同一章节的
     财务报表块占了 5 个名额，把金块挤了出去）；第 7 题金块融合第 22 名。
2. **金块落榜 ≠ 答不出。** 第 4 题的金块融合第 24 名、根本没进 top10，答案却
   全中——同一指标在第三节与财务报表附注里也有披露，那些块进了 top10。第 10 题
   同理：金块（第二节主要会计数据）没进 top20，但 136.26% 在第三节讨论段落里
   也出现过。所以评测把「金块名次」与「本次 top10」并列给出，单看前者会误判。
3. **作答步有跑间波动。** 检索是完全确定性的（同一问题重复跑，两路召回与 RRF
   名次逐块一致）；而 DeepSeek 即便 `temperature=0.0` 也不严格确定。在同一份
   索引上重复评测，总分在 **6/10 与 7/10 之间摆动**，摆动的总是第 10 题这种
   「关键数字落在 top10 边缘块」的题，第 1~8 题的判定三轮完全一致。

**这几题没有去「修」。** 答案在原文里都能逐字找到（第 7 题的金块里甚至有一句
原文直接写着「归属于上市公司股东的净利润13.43亿元，同比增长1,324.10%」），
失败纯粹来自固定的 top10 上下文与打分边界。把最终上下文扩到 top20、或对全景题
按公司分组召回确实能命中，但那会违反题目对检索链路的约束，因此只记录、不改。
系统在缺少金块时的行为是**说明「资料中未直接给出」、把自算值标注为推算**，
而不是编造原文口径——按 prompt 里「禁止编造与先验补充」的要求，这是正确的保守
行为。

`data/table_check.md` —— 随机抽 5 个表格，把解析出的数字与 PDF 原文逐一比对：
抽样的 **262 个数字全部一致（100%）**；另做 20 轮多种子重复抽样，**3486 个数字
全部一致**。核对基线的已知局限（PyMuPDF 会切碎长数字、粘连相邻单元格）也一并
记录在该文件里。

## 九、已知限制

- 页码为 PDF 物理页码，与报告印刷页码可能偏移。
- 表格为 PDF 版式还原结果：同一页上版面连续的多张子表可能被 pdfplumber 识别为
  一张表（子表头会作为数据行保留在表中），数据本身不丢失。
- 部分无框线的多列排版（如「释义」两栏）依赖 span 间距启发式还原。
- **召回上限**：最终上下文固定 top10，因此跨 14 家公司的全景比较题无法在
  一次召回里覆盖全部公司（见第七节）；个别「关键数字只出现在某个边缘块」的
  公司内题也会擦线落榜。这是题目指定的融合规则的固有边界，不是解析问题。
- **作答步非严格确定**：DeepSeek 即便 `temperature=0.0` 也有跑间差异，边界题
  （关键数字落在 top10 边缘块里）的自动判定会在命中与不命中之间摆动。
- **语义地图的坐标只能看局部**：t-SNE 保的是邻域结构，**簇与簇之间的距离、簇的大小
  都没有可解读的含义**（两张公司孤岛靠得近不代表业务相近）；PCA(50) 预降维也只保留
  78.3% 的方差。要比较两点的远近，请以它们的向量余弦为准（页面上召回的分数就是）。
- **`file://` 双击路径的提问**依赖浏览器放行页面 → `127.0.0.1` 的跨域请求。服务端一侧
  已实测正确（`Origin: null` 预检 200 并回 `Access-Control-Allow-Origin: null`、
  `Access-Control-Allow-Private-Network: true`），但**浏览器一侧（尤其是 Chrome 的本地
  网络访问限制）无法在本机自动验证**——若被拦，服务端日志里不会出现 `[rag] 提问`
  这一行，页面上也会给出改用 `http://127.0.0.1:8077/visual.html` 的指引。
  服务托管路径不受此影响。
- 语义分组里「管理层讨论与分析」有 444 块而非 443：有 1 个块的章节名是解析遗留
  （切块时把一句交叉引用当成了章节标题，见 `build_viewer.py:classify_group`）。
  各组的块数由代码现算并在页面上显示，没有写死。
